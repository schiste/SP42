# ADR-0033: Content-Security-Policy for the browser, server, and desktop shell

**Status:** Accepted
**Date:** 2026-09-28
**Author:** Christophe Henner (drafted with Claude)
**Summary:** Every SP42 response carries a restrictive Content-Security-Policy, and the desktop shell's CSP drops `'unsafe-eval'` and the blanket `https:`/`wss:` connect-src scheme-sources that let injected script exfiltrate to any host; removing `'unsafe-inline'` from `script-src` is the tracked next step.

## Context

ADR-0032 closed the unsanitized-HTML path by allowlisting rendered revision
markup at the server fetch edge. That is the primary control. CSP is the
containment layer: it bounds the blast radius when the primary control is wrong,
when a dependency misbehaves, or when a future change adds a new HTML source.

The audit that motivated this found no CSP anywhere:

- `sp42-server` applied no security headers. `tower-http` was wired for `cors`
  and `fs` only; there was no `set-header` layer and no
  `Content-Security-Policy`, `X-Content-Type-Options`, or `Referrer-Policy`.
- `index.html` carried no CSP `<meta>` tag — only cache-control metas.
- The desktop Tauri config did set a CSP, but two of its directives defeated
  their own purpose:

  ```
  script-src   'self' 'unsafe-inline' 'unsafe-eval' …
  connect-src  'self' … https: wss: …
  ```

  `'unsafe-eval'` permits `eval`-based execution. And the bare `https:` and
  `wss:` scheme-sources in `connect-src` permit **fetch to any host at all** —
  which is precisely the capability an attacker needs for exfiltration. Those two
  sources alone made the rest of the policy decorative for script that runs.

This matters more than usual here because the desktop shell is a Tauri webview:
JavaScript reaching the document can invoke `__TAURI_INTERNALS__.invoke` against
the sidecar. `object-src 'none'` and `frame-ancestors 'none'` were already
correct there; the script and connect directives were not.

## Decision

1. **The server sets CSP, `X-Content-Type-Options`, and `Referrer-Policy` on
   every response** via `tower-http`'s `set-header` layer, applied in
   `build_router`. All use `if_not_present` so a route that deliberately sets one
   of these headers keeps its own value.

2. **The policy is restrictive where it can be.** `default-src 'self'`;
   `object-src 'none'`; `frame-src 'none'`; `frame-ancestors 'none'`;
   `base-uri 'self'`; `form-action 'self'`. The last two close the
   base-URI-rewrite and form-hijack vectors.

3. **`connect-src` is an explicit host list, not a scheme-source.** Only `'self'`,
   the per-wiki Wikimedia API hosts, and the local coordination sockets. A
   regression test asserts no bare `https:` / `http:` / `*` source is present, so
   the exfiltration hole cannot be reintroduced by a later edit.

4. **The desktop CSP drops `'unsafe-eval'` and the blanket `https:` / `wss:`
   scheme-sources**, keeping the explicit Wikimedia host list. `object-src`,
   `frame-src`, `frame-ancestors`, `base-uri` and `form-action` are added to
   match the server policy.

5. **`'unsafe-inline'` stays in `script-src` on both surfaces, deliberately and
   visibly.** It is required by the current Trunk/Leptos bootstrap, which
   evaluates an inline module script. Removing it is blocked on a bundler-level
   change, not a policy decision. It is recorded as the primary follow-up below
   rather than being quietly shipped as an unexplained exception.

## Why the server sets CSP when the app is served from it

The browser shell and the API share an origin, so a single server-set header
covers both the HTML document and every JSON response, and it applies to the
localhost, VPS, and desktop-sidecar deployments without per-shell configuration.
`index.html` is generated by Trunk and served as a static asset, so a `<meta>` tag
there would be a second, divergent copy of a security policy; the header is the
single place that decides it.

## Alternatives considered

**CSP only, no sanitizer (or the reverse).** Rejected. CSP is a mitigation, not a
control: it cannot express "this specific markup is safe", and it depends on the
browser honouring it. ADR-0032's allowlist is the control; this ADR is the
containment. Neither replaces the other.

**Keep `'unsafe-eval'` in the desktop CSP for Leptos.** Rejected on the evidence:
the Trunk production bundle does not require it, and `'unsafe-eval'` widens the
execution surface for every future script-injection bug with no offsetting
benefit. If a build genuinely needs it, that is a signal to revisit the bundler
setup explicitly.

**Blanket `https:` in `connect-src` for convenience.** Rejected — it is the
exfiltration primitive. Per-host entries are more verbose but are the difference
between a policy and a decoration.

## Consequences

1. **Exfiltration from injected script is blocked** on both the browser and
   desktop surfaces: a script that runs cannot `fetch` to an arbitrary host.

2. **Framing, plugin, and form-hijack vectors are closed** on the server for the
   first time.

3. **Debug parity improves.** The operator's browser console previously had no
   policy to report; CSP violations are now visible as console errors, which makes
   a future regression obvious instead of silent.

4. **A new gate is needed and does not yet exist.** CSP is easy to weaken by
   accident in a later edit, and the only protection today is the unit test in
   `security_headers.rs` (which does assert the `connect-src` invariant). Wiring
   this into `check-design-system.sh` or a dedicated policy check is follow-up
   work, listed below.

5. **Tracked follow-ups, in priority order:**
   - Remove `'unsafe-inline'` from `script-src` on both surfaces, by moving the
     Leptos bootstrap out of an inline module script (bundler/config change).
     This is the last remaining reason the desktop webview would execute inline
     script at all.
   - Add a CI gate asserting the policy invariants (no bare scheme-sources, no
     `'unsafe-eval'`, `object-src`/`frame-src`/`frame-ancestors`/`base-uri`/
     `form-action` present) across both the server source and
     `tauri.conf.json`, so neither can regress silently.
   - Re-review the `connect-src` host list when per-wiki host resolution changes
     (ADR-0014 commits to arbitrary Wikimedia projects, so this list is
     expected to need widening — it must be widened by explicit host, never to
     `https:`).
